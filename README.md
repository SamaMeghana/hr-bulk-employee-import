# HR Bulk Employee Import

MuleSoft 4 application that imports employee records from CSV or XML, validates each record, writes valid records to MySQL, creates a reject file for invalid records, and exposes run-status APIs.

## What you must install

- Anypoint Studio 7.x with Mule runtime 4.6.x.
- JDK 17.
- Maven 3.8+ if building from the command line.
- MySQL 8.x.
- Optional: MailHog for local email testing.

The application does not contain production passwords or tokens. You must provide the database and SMTP credentials during setup.

## Fast local setup with Docker

```bash
docker compose up -d mysql mailhog
```

The database is exposed on `localhost:3306`; MailHog SMTP is on `localhost:1025` and its UI is on `http://localhost:8025`.

Create the application database user and schema:

```bash
mysql -h 127.0.0.1 -u root -proot < src/main/resources/sql/ddl.sql
mysql -h 127.0.0.1 -u root -proot -e "CREATE USER IF NOT EXISTS 'hr_app'@'%' IDENTIFIED BY 'change-me'; GRANT ALL PRIVILEGES ON hrdb.* TO 'hr_app'@'%'; FLUSH PRIVILEGES;"
```

For a non-Docker MySQL installation, run `src/main/resources/sql/ddl.sql` with an administrator account and grant the configured application user access to `hrdb`.

## Secure password setup

1. Copy `src/main/resources/config/app-config-secure-dev.yaml.example` to `src/main/resources/config/app-config-secure-dev.yaml`.
2. Replace the example encrypted values with values generated by the Mule Secure Configuration Properties Tool.
3. Never commit the copied secure file or the encryption key.
4. Run Studio with JVM properties `-Dmule.env=dev -Dmule.key=<your-key>`.

The secure file is intentionally ignored by Git. For CloudHub, configure the secure file values and `mule.key` as deployment properties/secrets rather than committing them.

For local MailHog, the example credentials are acceptable. For a real SMTP provider, use an app password or secret, not your normal account password.

## Configuration

Non-secret values are in `src/main/resources/config/app-config-dev.yaml`:

- File folders: inbound, archive, error, and reject directories.
- MySQL host, port, database, and user.
- SMTP host, port, user, and sender.
- Validation threshold and accepted employment types.
- HTTP port.

The default folders are under `/tmp/hr`. Create them before starting:

```bash
mkdir -p /tmp/hr/{inbound,archive,error,reject}
```

## Build and run

From the repository root:

```bash
mvn clean test
mvn clean package -DskipTests
```

In Anypoint Studio, import the project as an existing Maven project and run it with:

```text
-Dmule.env=dev -Dmule.key=<your-key>
```

The packaged application requires access to the MuleSoft repositories configured in `pom.xml`. A MuleSoft/Anypoint account may be required to resolve Mule Enterprise artifacts.

## Importing a file

Place a `.csv` or `.xml` file in `/tmp/hr/inbound`. Files are moved to `archive` after successful/partial processing and to `error` after a fatal failure. Rejected records are written to `reject`.

CSV columns must be exactly:

```text
employeeId,firstName,lastName,dateOfBirth,dateOfJoining,officialEmail,mobile,departmentCode,designation,locationCode,employmentType,managerId
```

Dates must use `yyyy-MM-dd`. XML must use the `employeeImport/header`, `employeeImport/employees`, and `employee` structure shown in the sample fixtures.

## API checks

After startup:

```bash
curl http://localhost:8081/api/v1/health
curl 'http://localhost:8081/api/v1/runs?limit=20'
curl http://localhost:8081/api/v1/runs/<RUN_ID>
curl http://localhost:8081/api/v1/runs/<RUN_ID>/rejects
```

## Behavior and safety

- Duplicate files are detected by file name and SHA-256 checksum.
- Records are validated before employee persistence.
- If the rejection percentage exceeds the configured threshold, the run is aborted before employee writes.
- Invalid records are stored with a reject code and reason and are emitted in the original input format.
- Logs and email summaries do not include date of birth, mobile numbers, compensation, passwords, or tokens.
- Do not put credentials in DataWeave, XML, sample files, or committed YAML.

## Troubleshooting

- `Unable to resolve placeholder`: confirm `-Dmule.env=dev`, the non-secret YAML exists, and the secure YAML was copied from the example.
- Database connection errors: verify MySQL is running, port `3306` is reachable, the schema was applied, and the `hr_app` password matches the secure property.
- SMTP errors: start MailHog or configure a reachable SMTP server and valid app password.
- No files are processed: verify the inbound directory exists, the file has a `.csv`/`.xml` extension, and the Mule process can read it.
- Maven cannot resolve Mule artifacts: configure Anypoint/MuleSoft repository credentials in Maven settings and retry.

Generated files such as `target/` and local secure configuration must remain uncommitted.
